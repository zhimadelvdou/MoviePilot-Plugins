# Manko 自动触发

用户要求“增加自动触发”。当前按已配置的 `Qb` 下载器与精确 `AV` 标签，采用下载完成后的五分钟轮询；已告知用户可改为目录新增触发。沿用本地源 `/media/Qbit/AV`、目标 `/media/Link/电影` 和原生硬链接、重命名、刮削，不修改核心或主前端。

## 行为

- 复用现有下载完成发现与原生交接，不增加独立下载器连接、后台线程或文件搬运。
- 默认只处理自动触发启用后完成的下载；用服务端持久启用时刻核验原始完成时间，旧下载后补标签仍不能放行。
- 严格完成状态、精确标签、下载器、真实目录、下载清单所有权及文件版本校验继续生效。
- 重载不改变启用边界；用户禁用后重启用或改变任务范围才重新设定边界。时间字段缺失或状态损坏时停止，不回扫历史。
- 页面显示自动状态及启动边界，提供只读条件检查；原手动入口保持可用。

## 验收

- 新旧完成时间、无效时间、重载、重新启用、范围变化、持久状态损坏及未认证接口有回归。
- 使用原有隔离真实 SDK 验证；不叠加核心补丁、不挂载生产媒体。
- 部署前备份，先保持自动关闭；通过已启动插件的 SDK 检查真实完成时间字段、目录监控冲突和触发配置。
- 只有真实完成时间可核验、无原生监控冲突且目录及硬链接条件成立时才开启自动整理；不修改其它自动监控规则来掩盖冲突。
- 不通过伪造生产下载或修改原始文件来冒充下载事件验收。没有新完成任务时，明确区分“已启用、待下一下载”与“真实任务已完成”。
