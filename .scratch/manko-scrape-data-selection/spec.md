# Manko 同番号完整数据包选择

## 目标

同一规范化番号命中多个 Manko 原生 ID 时，按公开搜索 API 的返回顺序逐个核验；选择第一个在本 ID 的详情与演员接口中具备完整刮削字段的数据包。只返回该 ID 的原始记录和演员列表，不合并不同 ID 的任何字段，也不基于 ID、译文数量、评分或其它未映射字段择优。

## 完整度

- 标题：有效的 `title_display_name` 非空数组中每一行都须有非空语言和标题；数组缺失、null 或为空时可使用既有非空平面 `title`。
- 简介：`discription` 非空数组的每行都须有非空语言和 `overview`。
- 日期：沿用当前 `share_date` ISO 日期规则。
- 图片：封面是安全 HTTPS URL，且至少一个安全 HTTPS 背景 URL 与封面不同。检查来源完整性不依赖用户可选的 `image_hosts` 配置。
- 演员：当前 ID 对应的演员响应必须是非空、有效且未显示截断的列表。

语言不设硬编码白名单；额外未知字段、资源字段、片长、rating 与 `avdbs_actor` 差异不影响完整度。标题/简介译文及图像 URL 均不跨 ID 合并。若所有精确匹配候选均不完整，搜索返回空，并记录固定缺项标签 `title`、`descriptions`、`date`、`cover`、`background`、`actors`。

## 边界与兼容

搜索仍要求精确番号、完整且受限的搜索总数、有效原生 ID、详情身份一致。唯一匹配与直接原生 ID 查询保持既有行为；非 Manko 来源不变。只改变 Manko 番号查询缓存策略键，避免复用旧选择策略的号码缓存；原生 ID 缓存键和其它来源键不变。

## 验收

同步/异步 `search` 与 `search_matches` 必须都返回同一个 API 顺序下的单一完整 packet；无完整 packet 时均返回空。回归覆盖首个完整但 ID 非最小且字段与后项不同、首项各类字段缺失时的后项回退、全部不完整拒绝、无效总数 fail-closed、平面标题兼容、演员原样保留和旧号码缓存键不复用。
