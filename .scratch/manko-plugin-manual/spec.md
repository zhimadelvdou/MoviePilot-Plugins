# Manko 插件独立手动整理

用户于 2026-10-22 选择接受插件页入口，要求保留现有修改，独立方案不修改 MoviePilot 核心或前端。

## 行为

1. 在插件自己的页面选择本地源文件或目录、已有目标目录与元数据来源；首版仅支持硬链接。
2. 根据文件名或目录名提取唯一番号并查询来源，不要求用户手填 ID。
3. 显示标题、来源、原生 ID、原路径及预计目标；识别冲突或失败必须明确显示。
4. 用户预览后才可明确提交；只提交成功、尚未提交且未过期的服务端预览意图。
5. 由 MoviePilot 现有公开整理能力建立硬链接、重命名和刮削，保留原文件。

## 约束

- 仅修改插件仓库；不修改核心、主程序前端、全局默认来源，不拦截其他来源。
- 使用官方 Vue 联邦页面、插件 API、来源模块及公开整理入口；不依赖本地热修 `recognize_source`。
- 沿用插件配置中的本地触发目录；目录范围为空时阻止源文件扫描与整理，明确提示配置。
- 不开启 qBittorrent 自动发现或定时整理；手动入口与现有自动账本分离。
- 预览不修改媒体文件；实际提交防重复，网络异常或重启后结果不明不得自动重提。
- 不允许删除、移动或覆盖源文件；不允许任意浏览宿主目录或客户端自造媒体身份。

## 验收

- 在热修前真实 MoviePilot 运行时副本、真实依赖中运行，不叠加核心补丁。
- 隔离临时文件验证“插件识别 → 原生预览 → 原生硬链接与重命名”，校验源内容不变及源/目标 inode 一致。
- 对 NFO、图片的真实落盘单独报告验证范围；提供方使用合成离线数据，不访问真实网络。
- 页面/API 覆盖未认证、目录越界、链接逃逸、文件变化、重复执行、来源未启用、失败与结果未知等边界。
- NAS 上先保留备份，再仅更新插件；真实下载文件的实际整理需在精确目录与操作已授权后执行，不能用预览冒充完成。
